# Shared course style in Arm Assembly Lab

Copyright © 2026 Christopher Snow.

Follow the [shared course design guide](https://github.com/snowch/cuda-python-lab/blob/main/docs/course-design-guide.md). This adapter preserves the course's stated C and binary prerequisites, instructional gates, real simulator-derived figures and existing lesson URLs and storage keys.

The header keeps Calculator, Reference, App status and the theme selector. The assembler, simulator and small local C compiler are JavaScript model code. There is no prepared WASM runtime to start, hold or release, so there is no Code runner header control. The optional Compare with GCC remains an explicitly requested external comparison.

Typography uses locally bundled IBM Plex Sans and Plex Mono with their OFL licences. Reading text is 17 px, ordinary code 16 px, headings restrained and shared shell controls at least 44 px. Theme roles supply surfaces and contrast. The existing live homepage model stays beside the introduction on wide screens and follows course choices on narrow screens; it is not a decorative or scripted substitute for execution.

A combined Course lessons row shows explicit reading progress and current module/lesson. The inline outline preserves ordinary lesson links, uses the existing course-position formatter for numbered destinations, and closes with Escape. The separate On this page disclosure still reaches real sections and moves focus to their heading. Neither menu remounts the lesson model or clears entered work. Resource references stay optional; explicit, reversible completion remains separate from challenge grading. Previous/next cards name their actual lesson. They share a row on wide screens and stack at equal widths on phones. Reset inherited explicit grid-column positions when stacking; a leftover second-column declaration creates an implicit column and squeezes the previous card.

References uses the shared full-width resource row: an official 24 px `menu_book`, the title, existing instruction scope and a 20 px `chevron_right`. The chevron rotates on opening, and the whole summary remains a keyboard and touch target. Expanded instruction forms, source links and authored reference notes remain intact. Instructionless lessons reuse their approved title for scope; placeholders such as `B.cond` keep the catalogue's case. A single divider separates the ending rather than duplicating adjacent borders.

The shared shell uses official Material Symbols Rounded geometry for references, header tools, theme, outline and completion. SVGs and their exact Apache licence and pinned provenance are local; verify the licence and provenance in the built offline manifest, not only in the source checkout. Subject-specific model diagrams and module marks remain course-owned; existing instructional view icons are not claimed as migrated. Keep visible brand and tool names at every width, and remove inherited icon-only widths when restoring those labels. The native theme selector keeps both a visible label and visible choice.

Completion is a reversible persistent toggle with an explicit pressed state, followed by the separate navigation cards. First and final cards return to the overview on the boundary side. The quiet footer keeps Where next?, Source, Sources and licences, Report a problem and attribution. Companion descriptions and links remain on the optional Where next page, including the no-script page. Commit/date/build identity belongs in App status.

App status is a persistent native modal with a dimmed backdrop, one Course status section and one prominent applicable action. Measured progress and recovery stay visible; version/source identity, manual checks and removal stay in optional details. Escape dismisses the top modal, returns focus to its trigger and preserves an underlying desktop Calculator or Reference lookup. See [offline operation](offline.md) for loaded, published and saved release identities.

Verification records, separate copy drafting and independent technical/learner findings are in [shared-course-style notes](notes/shared-course-style/). The [completion audit](notes/shared-style-completion/brief.md) records the later icon, label and footer corrections. Browser checks verify functional behaviour and presentation; they do not establish learning effectiveness.
