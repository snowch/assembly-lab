## Assessment from source

No mathematical or grading blocker found. The new published lesson follows `same-bits-two-readings` and precedes `arithmetic-on-register-bits`. The prerequisite teaches positional contributions and the signed highest weight; this lesson introduces carrying and inversion before requiring them. The four-bit range and signed worked subtraction are correct. The local statement, “These signed values fit”, qualifies the worked signed reading rather than promising that every four-bit subtraction represents an exact signed result.

The cancellation explanation is sound: a four-bit pattern plus its inversion has every position set; adding one leaves zero in the retained positions. That establishes a fixed-width additive opposite. The complete worked example constructs that opposite and then adds it, without using the fresh exercise's inputs or answers. The extra carry is kept visibly outside the four result positions in the width figure.

`fourBitAddition` derives columns from an actual 32-bit machine addition record. `columnWork` obtains the miniature's carry from the next column, including the carry beyond bit 3; it does not confuse that carry with the architecture's 32-bit C flag. `fourBitSubtraction` obtains its retained result from actual SUB execution; tests compare the separate opposite-and-add calculation with that result. Exhaustive tests independently check all input pairs, column recurrence, signed readings, and zero and signed-boundary cases. Input-domain checks reject non-integers and values outside four bits.

The new grader calculates expected patterns from each case's inputs. It blocks unanswered parts and rejects inversion without the extra one, a fifth retained bit, malformed or short patterns, and incorrect carry decisions. The format requirement is visible: “Use four binary digits”. Spaces are accepted without silently accepting a different number notation. Feedback identifies the affected calculation without providing an unearned expected pattern. The solved note uses the existing `passedChallenge` gate, which regrades saved work rather than trusting a stored completion mark.

The bridge to the next page says the width changes to 32 places and `sub` performs one instruction. It does not assert a four-bit Arm register or a particular physical adder circuit. The later Module 2 page retains the actual 32-bit inverted operand, initial carry of one, zero-second-input case and derivation of C as no borrow. Removing its redundant miniature has not removed the mechanism needed to understand its flags.

An edge distinction was checked and rejected as a defect: separately retaining a negated zero and then adding it is equivalent to SUB for result bits, but not necessarily for its carry. The new miniature does not display or grade Arm C. The later flag lesson correctly uses the single full-width inverted-operand-plus-one calculation, including the zero case. Do not reuse the miniature's two-stage addition carry as a SUB flag in a future extension.
