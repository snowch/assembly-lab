# App status layout validation

The supplied screenshot exposed a gap between phone and desktop coverage: the right-aligned panel was positioned relative to a narrower, centred button. Its left edge could leave the viewport. The panel now anchors to the full header, with width bounded by its gutters. The button contains the title, a disclosure mark and independent version/offline badges. Source identity and build/date remain inside the panel and the footer; the static entry also omits source identity from the button without claiming unverified state.

Compact offline labels and revised update guidance were drafted separately from the checked brief and edited against docs/style.md. The user-preferred Saved offline is used only for the existing verified ready state. Preparation alone does not create that state. The existing version states, offline inventory, transfer consent, worker protocol and saved-work restart guards are unchanged.

The initial conservative CSS height reserve contained the panel, but independent learner review found poor use of short landscape space at 150% text: an 87px border box left only 35px for content. The final implementation measures the space below the header, responds to header/viewport resizing and scrolling, and cleans up its observer/listeners. Independent final checks measured approximately 223px overall and 171px of content at 800x375/150%, with the focused Download control wholly visible and the document unscrolled.

Independent learner and technical reviews each checked 20 viewport/theme/text-size combinations: 375, 641, 800, 1280 and short 800x375, light/dark, 100%/150% text. Both approved the final built interface, contained panel, readable labels, internal scrolling and Escape/focus behaviour. Source details remain in the panel. Both also checked static/no-script entry; technical review additionally verified pre-hydration entry and live resize while open, and balanced observer cleanup. Physical mobile pinch zoom and on-screen keyboard interaction were not emulated; the visualViewport path was reviewed in source.

The new browser regression uses real production releases, inventories and service workers. It checks current/not-saved, saved, update-available plus saved, update-ready plus saved, deferred readiness, keyboard dismissal/focus, viewport bounds and at least 44px of content space with 150% text. Its exact available-state assertion is scoped to the panel section because the new summary badge repeats the same label; the state and Restart assertions are retained.
