## Decision and implementation

Keep the four-instruction exercise and its model-derived register expectations. Remove the by-hand/decimal-only requirements: the local task names decimal or explicit 0x hexadecimal, and the caption makes Calculator and Working notes optional. One of each appears after the listing and before the two answers, closed and blank for fresh work. Neither receives the listing, expected result, answer callback or grading state.

Calculator reuses bounded exact BigInt arithmetic with an opt-in hexadecimal mode. The new mode shows decimal and signed-magnitude hexadecimal output; it does not wrap to a machine width. Existing decimal calculators and the whole-division constant-building mode retain their help, output, parser restrictions, division semantics and handoff keys. Arithmetic input limits remain 200 characters, exponent at most 4096 and intermediate magnitude at most 2^16384 minus one. The new mode has its own handoff suffix. Ordinary calculator reload remains transient; closing/reopening retains work.

Only this challenge opts into decimal-or-hex numberFormat. Its answer fields request a text keyboard. The register grader uses the selected parser for both validation and comparison, still comparing exact signed/unsigned readings at the real width. It never masks an oversized submitted number into correctness. Default register/pattern/bit-reading graders stay decimal-only. Blank-answer, wrong-register, hint and completion rules remain.

Notes are separately stored by lesson/challenge under assembly-lab:notes:v1, never in graded artifacts. Editing notes preserves a verdict/completion. Clear work remounts/collapses the tools and clears graded work, while notes reload independently. Clear notes affects only notes. Actual browser-storage read/write/clear failure retains editable text and shows the separately drafted warning. The accepted correction below also retains unsaved text across editor remount and same-tab navigation. Protected-update state uses the existing view handoff. Successful save/clear removes the volatile fallback. No new platform or machine code, native listing, exercise reference or prior prediction gate changed.
