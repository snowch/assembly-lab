## Checked facts and drafting brief

The current instruction's load/store records determine accessed addresses and transferred bytes. `memoryTransferAt` computes copied bytes, register-only extension, zero/sign fill and upper-half clearing from the simulator's decoded operation and actual register state; no display value is guessed. The `memoryAt` snapshots retain unchanged neighbouring bytes and rewind writes. Little-endian transfers map increasing byte addresses to increasing register bit positions. Array grouping is explicit lesson metadata, not inferred from byte contents.

The reader findings in course-load-review/11–14 and 22 and independent middle/late challenges identify substantial reference travel. Core evidence must stay visible: exact addresses, bytes, array boundaries, copied versus filled/cleared regions, register values and relevant flags. The brief is to remove repeated role prose and align the compact source/bit mapping, keeping full inspection available. This agent is the separate drafting/implementation pass from the managing session's checked-fact brief. Learner text is kept in strings.memory.ts and the canonical module-6 prose record. No instruction or C-language semantics changed.

## Changes

- All addressed memory bytes remain visible in compact four-column strips. Declared array elements stay grouped. A single access legend replaces repeated visible per-byte access sentences; each byte retains its full accessible address/value/access description.
- Register transfer regions are grouped by adjacent model-derived roles, with one visible role/range label per copied, sign/zero-filled or cleared region. Individual byte values, bit ranges and source addresses stay visible. Address order and register-bit order both increase left to right, explicitly labelled; this removes the former three-plus-one versus reverse two-by-two correspondence.
- Optional binary strings use Show/Hide byte bits. The initial view still exposes all core byte-level effects. The full physical register's clearing remains a distinct region when the lesson requests extension.
- Read/source outlines are dashed and memory writes/destinations solid, with explicit labels. Colour is supplementary. Current operation/status, register state and flags remain with controls. Complete paired C is preserved.
- Loading-widths now has one same-source investigation with six instruction choices; array addressing has one offset/pre-index/post-index comparison. Switching preserves the executed instruction position and recomputes the selected trace, so before/after values never linger from another case. Actual address-used and address-register before/after values are beside the current operation. The full selected byte/extension mechanism precedes the wider memory context.
- Only these focused comparisons place the intact complete C/instruction pair in an optional Inspect C and instructions disclosure. The current/next instruction stays visible beside controls, including before any step. Ordinary first-load and transfer examples retain their full paired listing by default.
- Prediction gates, Next/Back/Reset, model-derived bytes and every addressed neighbour are preserved across all shared uses. No platform files, registries or lesson programs changed. Existing reference programs moved into nested comparison cases; no new machine program was invented.
