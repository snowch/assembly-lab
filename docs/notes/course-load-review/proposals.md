# Managing review: proposals for independent challenge

These are design proposals, not measured learning outcomes or automatically accepted findings. Challenge them against current source, entry prerequisites, reader notes and representative built states. Preserve rejected proposals and reasons in the ledger.

1. **Module 0: introduce the first operation before whole-function tracking.** Keep the motivating C example brief, then an assembly-only addition activity with two inputs and one destination; next show read-before-write; next subtraction; then argument/return convention and the complete paired function. Existing first-step explanation and optional bits/detail are useful. The user supplied repeated phone confusion; current first-step figure still combines paired listing, equation, four register summaries, operand rule/diagram and next task. Known C is not itself new, but relating C variables to reused registers and a moving instruction is new. Recommend a prototype and novice trial, not a claim that whole functions or four instructions inherently fail. Keep complete paired listings for C-derived synthesis; assembly-only primitive activities avoid inventing C or violating the mandatory paired-listing rule.

2. **Module 3 masks: practise the basic rules before field composition.** Move the existing AND/OR/XOR experiment before the field/extraction prose. Stage field replacement first with an in-range source, then introduce containment of an out-of-range source. Retain the full construction as synthesis, hints and post-success BFI comparison.

3. **Module 6 loads: vary one axis at a time.** Same byte/address first, signed versus unsigned extension, then source width, then destination width, then record reading. This is a candidate sequence improvement; familiar w/x clearing is not a new mechanism. Independently check whether the existing five steppers already stage these dimensions adequately before accepting. Separately fix unequal phone memory/register byte grouping.

4. **Module 8 multiplication: delay secondary alternatives where they interrupt the width question.** Candidate: basic low product, wider product and interpretation, then fused multiply-add/subtract and 128-bit high halves. Challenge this proposal: current construction deliberately practises MADD and low-bit semantics before widening, and addition is already known. Opcode count alone is no finding.

5. **Module 11 checked arithmetic: separate conversion rules from checked-add implementation.** Narrowing has prior teaching, but promotion and mixed-type conversion are new, checked-add API new, printf/varargs formatting new, sanitizer workflow new. Propose conversion practice followed by checked-add, with formatting/sanitizers as a distinct optional follow-on. The existing heading and supplied functions may already bound each task; inspect before accepting. Do not claim pointer/store/flags are new.

6. **Module 12 boot: introduce diagrams when learners first need them.** Move file-to-memory explanation beside linker inspection and startup recording beside entry/stack/storage explanation. First successful boot uses trusted supplied output routine; then inspect its polling loop; inspect UART setup/exception classes/board firmware as further depth. Keep the bootable assembly capstone and familiar arithmetic repair, not another C-only exercise.

7. **Shared interface: one current task, relevant state nearby.** At an instructional step keep the current instruction, action and changed state in a compact unit. Collapse detailed explanation and secondary representations on transition. Do not hide essential byte/stack/flag evidence. Check siblings rather than only Module 0. Mandatory complete C/assembly pairing means a change to C visibility needs an explicit course policy decision; no policy change is authorised by this review.

8. **Keep synthesis.** Loops, recursion, compiler comparison and native debugging should still combine previously practised mechanisms. Split by a new mental model or learner task, not universally one opcode per lesson. Prediction-before-explanation can be a deliberate low-stakes diagnostic; any-answer commitment is not a retry-until-correct gate. No blanket spoiler finding follows from worked examples before transfer questions.
