## Outcome and preparation

The learner can distinguish who chooses a suitable instruction form (a compiler or a person writing assembly) from who executes it (the processor). They can connect that choice to the existing fixed-amount example. The user's repeated who/when question is observed evidence of missing orientation, not proof of a general novice failure.

Earlier Fundamentals explains C compilation, instructions, immediate constants and the unshifted range. Loading a constant and Building a constant explain loading and fixed amounts. The local explanation retains its shifted constant, permitted range, source/destination and model-computed arithmetic. The new strip carries roles, not another calculation.

## Checked facts and limits

- A compiler can select ADD immediate for a suitable fixed addition; an assembly programmer can select that form directly. This is capability, not a claim that GCC generated the displayed course-written example.
- The processor executes the selected machine instruction. Selection is not another runtime arithmetic operation.
- The existing SHIFTED_IMMEDIATE_ADD and operand-additions facts/native corpus establish the displayed constant and arithmetic. No new program, numeric state or model operation is introduced.
- A fixed constant encoded by the instruction needs no separate constant register for this addition. Local range/shift restrictions remain essential and visible. GNU as can infer the shift from an equivalent plain larger immediate; do not claim that spelling is rejected.
- This is a static conceptual relationship, allowed by docs/visual-language.md, not a simulated compiler decision or an execution timeline. It never gains state-dependent highlights.
