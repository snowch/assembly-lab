# App status copy draft

Separate drafting pass from `brief.md`, read with `docs/style.md`. No component, worker or lesson changes made in this pass.

The panel has the issue's two sections and exact version/offline state labels. Its actions use the shared wording. Explanations name the effects of saving, cancelling, removing and restarting without service-worker or storage implementation terms. The restart notice names every Assembly Lab window; failure feedback keeps unsafe work in place and tells the reader what to do next. Offline limitations distinguish browser tools and example downloads from external services and native execution.

Computed totals and progress format supplied bytes. No size, percentage, duration or transfer rate is invented. The source-version fallback makes no commit claim.

Sentence pass: direct instructions, British English, no em dashes, one action or consequence per sentence where practical. Idea pass: the reader can distinguish checking for a release from saving a copy; removal preserves user content; offline readiness does not assert freshness. Final rendered state and technical guarantees require the independent reviews and browser checks in the implementation brief.

Removal failure feedback says some offline files may remain, preserves the user-work assurance and gives a specific retry action. It does not claim removal succeeded.

Learner review follow-up: incomplete-download guidance now says to resume when connected. It covers cancellation while already online without assuming the connection was lost.

Legacy partial-save migration: added `offlineRequiresUpdate`, directing the reader through the visible Update and Restart to update controls before Download for offline use. The draft does not expose the worker transition or imply that a disabled download action can work yet.

Added the standard label `Build` for the deterministic identifier of the loaded app files, displayed separately from the source commit. The label adds no invented identity or value.
