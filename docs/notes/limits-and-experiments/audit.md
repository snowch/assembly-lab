# Course experiment audit

The planning pass inspected the actual published lesson sequence, its grouped source definitions,
view schemas and canonical prose. This is a source audit, not a novice learning study. Final built
reviews concern the three changed lessons and the local subtraction range clarification.

| Area | Existing evidence and action |
| --- | --- |
| Register readings and widths | Add the early decimal100 retained-bits experiment. Keep W/X write comparisons. |
| Flags, wrap and negation | Existing signed/unsigned boundaries, zero, equality and near-minimum cases remain. Clarify local four-bit input bounds. |
| Shifts and masks | Add valid-input/output-discard versus rejected-input trials to the existing editable shift figure. Keep the field-mask oversized-input exercise. |
| Comparisons and branches | Existing equal, above/below, signed/unsigned disagreement and branch-edit predictions remain. Keep fresh assessment cases out of explorer presets. |
| Loops | Existing zero/equal/descending/maximum endpoint and exhausted-work cases remain. Add the broken-BEQ one-step interval counterexample. |
| Memory transfers | Existing narrow/wide store and load comparisons already expose low-bit retention and neighbouring bytes. Do not ask to edit read-only setup. |
| Arrays and strings | Existing empty, first/last, zero-capacity and bounded/no-terminator contracts remain. Do not invent an out-of-bounds experiment or equate simulator regions with C array bounds. |
| Products and division | Existing narrow/full product comparisons, zero divisor and signed-minimum assembly cases remain, with explicit C preconditions. |
| Calls and recursion | Base cases and preservation already appear in traces/exercises. A separately selectable zero/one original-recursion comparison is a possible later refinement, not a new editable control supplied by this change. |
| Local C compiler | Existing zero-count, loop-boundary and repeated-one-bit versus invalid single32-bit-shift activities remain. Keep tested-path diagnostics distinct from accepted input and assembly behaviour. |
| Native startup and board work | Existing fresh-session marker and source/build/board distinctions remain. Pending physical-board verification remains pending. A browser check cannot establish hardware boot success. |
| Optional floating point | Existing rounding/spacing exploration remains an exact numeric model. A zero/subnormal field-transition prompt is a possible later refinement. Native conversion recordings remain labelled recordings, not live browser execution. |

The implementation deliberately fills three concrete gaps instead of introducing another repeated
form, mandatory gate or checklist across every page. Informal predictions name observable fields,
then ask for the reason. Authored numerical cases are checked against the relevant model and native
corpus; diagnostics and accepted alternative experiments keep their distinct meanings.

Separate drafting and planning records are retained under the task evidence folder
`/workspace/work/limits-and-experiments/`, including the source-only learner/technical audit and
later-module audit. Those reports propose alternatives as well as selected changes; they are not
claims that every suggestion was implemented.
