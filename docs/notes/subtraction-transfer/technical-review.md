## Accepted finding and correction

The first guide drafts described the preserved-register lists as if they were exhaustive, omitting the stack pointer. AAPCS64 requires preservation of r19–r29 and SP; the RISC-V integer convention preserves s0–s11 and SP. Both copies now qualify the lists as general-purpose integer registers and explicitly require restoring SP before return. The inspected correction is consistent with the named conventions. Platform-specific and vector extensions remain outside these ordinary integer examples.

The new RISC-V guide originally said Start stepping paused before the first machine instruction, while also showing the supplied whole program. The builder selects `_lab_lesson_begin` for a fragment, and the worker executes setup before pausing there. Actual browser state confirmed the first lesson instruction at source line 1. Both guides now state that supplied entry/setup runs before pausing at the first machine instruction in the fragment. The final built RISC-V prose includes this qualification. This is a wording correction, not a change to execution.

## Source checks

- The four-bit reminder computes 0 minus 14 modulo 16: `1110` inverted is `0001`; adding one gives `0010`; adding the later reading retains `0010`. The model-derived counting path is 14, 15, 0, matching two increments.
- Every displayed arithmetic value comes from the existing four-bit models. Those models run real 32-bit ADD/SUB and select their low four bits for a clearly labelled teaching view. The view does not claim that native 32-bit 0 minus 14 returns two.
- The arithmetic rows are a worked calculation, followed by the one-`sub` explanation. The explicit four-to-32-bit bridge precedes the original real-width prediction. The miniature uses different announced inputs and does not expose that prediction's result. The original ring remains behind the original prediction gate.
- The elapsed-time interpretation retains both assumptions: normal forward counting and less than a full turn. The modulo difference cannot identify additional complete turns.
- The worked transfer functions use 64-bit operands and the ordinary first two integer argument registers, returning in the first result register. Their hand-written provenance is explicit; neither is claimed as compiler output.
- The new Arm task supplies three explicit 64-bit patterns, checks low-64-bit difference plus adjustment and preservation of the two named inputs. Its source uses only SUB, ADD and RET. Wide, wrapped and equal cases exercise the stated contract.
- The RISC-V caller enters the leaf with CALL, copies the returned a0 to the project's default displayed t2, and branches past the function body before the supplied capture. It does not execute a top-level RET without a caller.
- Width, zero-register, flag and direct-branch distinctions agree with the official ISA extracts and native instruction behavior. Core Arm function simulation is distinguished from the course's native activities and from the RISC-V GNU-built xv6 user process. The guide separates calling conventions from supplied register setup and process startup.

Primary checks used the official AAPCS64 2025Q4 source fetched from `ARM-software/abi-aa`, particularly the general-purpose register table and preservation rule, plus the official RISC-V ISA/psABI extracts in `/tmp/riscv-audit-{rv32,rv64,abi}.txt`.
