# Modules 10–A pacing implementation

The published lessons use `content/lessons/pacing-10-a.ts`. Original source lesson exports and
compiler/native records remain intact. No compatibility pages, saved-work migration or platform
changes are added by this module group.

## Page boundaries

- Module 10 uses eight activity units: trace a C calculation, equivalent assembly, changed source,
  capped C; then trace a loop, equivalent assembly loop, changed boundary and repeated shifts.
  Both original read pages already contain a listing, prediction and full compiler playground.
  Keeping their changed-source investigations separate avoids combining two complete runs. Every
  prediction remains beside its corresponding playground; each full loop and zero-count check
  remains intact. The source-edit invitation moves from the initial arithmetic read to its edit
  page. GCC service guidance stays with a compiler playground. Construction pages own their
  existing executable challenges.
- Module 11 retains signed overflow and its tested increment construction, trimming its repeated
  reflection and the general two-operand bounds detour. `checked-arithmetic` now covers conversion,
  promotion, mixed comparison and the pre-conversion range check. `checked-addition` owns the
  stored-result and overflow-report contract. `integer promotion` arrives on conversion;
  `sanitizer` stays with the checked-addition optional detail.
- Module 12 builds and boots before the detailed linker/startup inspection. `loading-and-startup`
  precedes the debugger lesson and owns the memory-layout, recorded startup and loading-path
  figures with a practical checkpoint. Its figures have no dependency on a prediction mounted on
  another page. The initial arithmetic and error predictions retain their local trace gates. The
  debugger's final task omits replaying the complete already-completed GDB session.
- Module 13 has four complete workflows: preparation/connection; build/staging; card, serial
  terminal and first boot; deliberate failure, restoration and diagnosis. The install/extract/build
  command block stays whole. The first terminal opening and closing stay together; changed and
  restored runs stay together. Evidence recording appears beside its producing activity. Physical
  hardware verification remains pending on the independent pages.
- Optional A uses four recorded comparisons: register/return conventions, conditions/syntax,
  constants and division helpers. Existing recorded-token queries/cases split into local return,
  conditional, constant and division exercises. No answer is invented. The redundant marker
  reference formerly beside the division exercise is removed; the full marker pair is local to
  the constant activity. A32 remains static; all interactive execution remains A64.
