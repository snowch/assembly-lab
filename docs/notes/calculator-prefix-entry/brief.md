# Prefix-based header calculator entry

The user approved removing both format dropdowns and teaching decimal by default, hexadecimal with `0x` and binary with `0b`. They also asked how 32/64-bit paste mismatches should behave. Keep the selected width stable: accept patterns whose numeric value fits and zero-fill unused upper positions; reject values requiring a nonzero bit above that width. Leading zeros do not make a fitting value too large. Do not sign-extend based on pasted length. An explicitly selected width change keeps its existing low-bit truncation/zero-filled widening behaviour; typing/pasting never triggers it.

Outcome: enter each operand in the intended base and predict whether the selected width can store its pattern, without coordinating a separate format selector. The observed failure is a prefixed hex value rejected because Decimal remained selected. This is a tool-entry correction, not a new lesson or an arithmetic exercise. Earlier binary/hex and signed-reading lessons supply preparation; the global header remains available before them and needs concise local guidance.

Checked baseline: the existing machine calculator uses BigInt, validates decimal against selected signed/unsigned limits, accepts hexadecimal as a raw nonnegative bit pattern regardless of signed reading, removes spaces/commas/underscores, rejects oversized significant values and preserves the original value after invalid entry. The header uses this model and preserves A until Apply. B controls are independent; Calculate keeps A, B and retained result aligned. Existing contextual lesson calculators still use explicit decimal/hex selectors and must keep working.

Implement automatic prefix parsing in the machine package. Unprefixed `1010` is decimal, even if it contains only binary digits. Prefixes are case-insensitive; binary accepts 0/1 only; unsupported prefixes, incomplete forms and negative prefixed patterns fail locally. Decimal negatives follow the signed reading. 32-bit hex/binary patterns entered at 64 bits zero-fill; 64-bit patterns entered at 32 bits fit only when upper bits are zero. No silent truncation, auto-width change or paste-length sign inference. Shift amounts and half editors remain explicitly decimal counts/values.

Keep pending A/B drafts separate from loaded values and invalidate output when an applied operand changes. Remove redundant format selectors and their CSS layout column. Preserve typed notation through ordinary close/reopen and route changes. Existing explicit width narrowing may truncate the loaded A, but a too-large pending A/B stays available for correction and fails validation until it fits.

Coordinated-update handoff must migrate prior explicit hex fields, including bare digits, by marking them `0x`; do not reinterpret a saved hex `10` as decimal `10`.
