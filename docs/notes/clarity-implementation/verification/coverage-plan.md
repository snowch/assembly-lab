# Independent verification plan

Read-only verification of the implementation requested after the whole-course clarity audit. No finding is certified before checking the final built page.

Each of the 24 lessons receives a fresh reader who has not authored its changes. The reader first reads the actual page, source and relevant earlier prerequisites, then checks the accepted issue list. Browser configurations: 375 and 1280 pixels, light and dark. Readers quote issues, state severity and evidence, and suggest correction directions without drafting text or revealing challenge answers. Each report names interaction limits and unexplained assumed knowledge.

The coordinator independently challenges findings and checks changed technical claims against recorded listings, simulator behaviour and the repository's named sources. Root runs the full automated check separately. Shared-component findings are grouped rather than counted per lesson. Final acceptance requires checking any corrections in the final production build.
